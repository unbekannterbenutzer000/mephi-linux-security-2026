# ДЗ №1. Изучение средств защиты ОС GNU/Linux

## Раздел 1. Создание пользователя

### 1.1. Создание пользователя

`getent passwd 1234` - для проверки, что UID 1234 не занят другим пользователем

`id user1` - для проверки, что пользователь с именем user1 не существует

`getent group students` - для проверки наличия группы students

`sudo useradd -m -u 1234 user1` - для создания пользователя user1 с UID 1234

- `-m` - создать домашний каталог пользователя `/home/user1`
- `-u 1234` - назначить пользователю UID 1234

`id user1` - для проверки создания пользователя и назначенного ему UID

`sudo groupadd students` - для создания группы students

`getent group students` - для проверки создания группы students

`sudo usermod -aG students user1` - для добавления пользователя user1 в группу students

- `-a` - добавить пользователя в группу без удаления его из остальных групп
- `-G students` - указать дополнительную группу students

`getent group students` - для проверки членства пользователя user1 в группе students

`sudo chage -M 90 user1` - для установки максимального срока действия пароля пользователя user1 равным 90 дням

- `-M 90` - максимальное количество дней между сменами пароля

`sudo chage -l user1` - для проверки параметров срока действия пароля пользователя user1

`sudo passwd user1` - для назначения пароля пользователю user1, необходимого для дальнейшей проверки работы sudo


## Раздел 2. Мониторинг файлов и процессов

### 2.1. Мониторинг файлов

`sudo find / -type f -perm -4000 -print 2>/dev/null` - для поиска в системе обычных файлов с установленным битом set-UID

- `/` - выполнять поиск по всей файловой системе
- `-type f` - искать только обычные файлы
- `-perm -4000` - искать файлы с установленным битом set-UID
- `-print` - вывести пути найденных файлов
- `2>/dev/null` - не выводить диагностические сообщения из stderr

`ls -l /usr/bin/sudo` - для просмотра владельца и прав доступа к файлу `/usr/bin/sudo` и проверки наличия бита set-UID

`sudo find / -type f -perm -4000 -print 2>/dev/null > ~/setuid-files.out` - для сохранения результатов поиска файлов с set-UID в файл

`cat ~/setuid-files.out` - для просмотра и проверки сохранённых результатов поиска


### 2.2. Мониторинг процессов

`ps -eo ruid,euid,pid,comm` - для вывода процессов с реальным UID, эффективным UID, PID и именем процесса

- `-e` - вывести все процессы
- `-o` - задать отображаемые поля
- `ruid` - реальный UID процесса
- `euid` - эффективный UID процесса
- `pid` - идентификатор процесса
- `comm` - имя выполняемой команды

`ps -eo ruid,euid,pid,user,comm,args` - для дополнительного просмотра процессов с именем пользователя и полной командной строкой

- `user` - эффективный пользователь процесса
- `args` - командная строка процесса

`ps -eo ruid,euid,pid,user,comm | awk 'NR==1 || ($1 >= 1000 && $1 < 65534 && $2 == 0)'` - для вывода заголовка и процессов, у которых реальный UID относится к обычным пользователям, а эффективный UID равен 0

- `NR==1` - вывести первую строку с заголовками
- `$1 >= 1000` - RUID относится к диапазону обычных пользователей
- `$1 < 65534` - исключить специальный UID 65534 (`nobody`)
- `$2 == 0` - эффективный UID процесса равен UID пользователя root

В результате был обнаружен процесс `fusermount3` с RUID 1000 и EUID 0, поэтому дополнительный запуск `passwd` для создания такого процесса не потребовался.

`ps -eo ruid,euid,pid,user,comm | awk 'NR==1 || ($1 >= 1000 && $1 < 65534 && $2 == 0)' > ~/monitoring-processes.out` - для сохранения результатов мониторинга процессов в файл `monitoring-processes.out`

`cat ~/monitoring-processes.out` - для просмотра и проверки сохранённых результатов


## Раздел 3. Изучение механизма set-UID

### 3.1. Выбор утилиты

В качестве существующей утилиты выбрана `/usr/bin/cat`.

В качестве привилегированной операции выбрано чтение файла `/etc/shadow`, доступ к которому обычному пользователю запрещён.

`sudo -u user1 /usr/bin/cat /etc/shadow` - для проверки невозможности чтения файла `/etc/shadow` обычным пользователем user1

- `sudo -u user1` - выполнить последующую команду от имени пользователя user1
- полученный отказ в доступе подтверждает, что обычных прав user1 недостаточно для чтения `/etc/shadow`


### 3.2. Выполнение привилегированной операции с помощью механизма set-UID

`sudo cp /usr/bin/cat /home/user1/cat-suid` - для копирования утилиты cat в домашний каталог пользователя user1

`sudo chown root:root /home/user1/cat-suid` - для назначения пользователя root владельцем файла `cat-suid`

- первый `root` - пользователь-владелец файла
- второй `root` - группа-владелец файла

`sudo chmod 4755 /home/user1/cat-suid` - для установки бита set-UID и прав доступа к файлу `cat-suid`

- `4` - установить бит set-UID
- `7` - права `rwx` для владельца
- `5` - права `r-x` для группы
- `5` - права `r-x` для остальных пользователей

`sudo ls -l /home/user1/cat-suid` - для проверки владельца, прав доступа и наличия установленного бита set-UID

В результате файл имеет права `-rwsr-xr-x` и принадлежит пользователю root. Буква `s` в правах владельца подтверждает наличие set-UID.

`sudo -u user1 /home/user1/cat-suid /etc/shadow` - для проверки выполнения привилегированной операции: чтения файла `/etc/shadow` пользователем user1 с помощью копии cat с установленным битом set-UID

Операция выполняется успешно, поскольку при запуске файла, принадлежащего root и имеющего set-UID, процесс получает эффективный UID владельца файла, то есть EUID 0.


## Раздел 4. Изучение механизма привилегий

### 4.1. Выбор утилиты

В качестве существующей утилиты выбрана `/usr/bin/chown`.

В качестве привилегированной операции выбрано изменение владельца файла с пользователя user1 на пользователя root.

Для выполнения операции используется Linux capability `CAP_CHOWN`.


### 4.2. Выполнение привилегированной операции с помощью механизма привилегий

`sudo cp /usr/bin/chown /home/user1/chown-cap` - для копирования утилиты chown в домашний каталог пользователя user1

`sudo ls -l /home/user1/chown-cap` - для проверки наличия скопированной утилиты, её владельца и прав доступа

`sudo -u user1 getcap /home/user1/chown-cap` - для проверки отсутствия назначенных файловых capabilities у `chown-cap` до настройки

- отсутствие вывода означает, что capabilities у файла не установлены

`sudo -u user1 touch /home/user1/cap-test.txt` - для создания тестового файла от имени пользователя user1

`sudo -u user1 ls -l /home/user1/cap-test.txt` - для проверки владельца тестового файла

Первоначально владельцем файла является пользователь user1.

`sudo -u user1 /usr/bin/chown root /home/user1/cap-test.txt` - для проверки невозможности изменения владельца тестового файла на root обычным пользователем user1 с помощью стандартной утилиты chown

Команда завершается ошибкой `Операция не позволена`, поскольку обычный пользователь не имеет требуемой привилегии.

`sudo -u user1 ls -l /home/user1/cap-test.txt` - для проверки того, что после неуспешной операции владельцем файла остался user1

`sudo setcap cap_chown=ep /home/user1/chown-cap` - для назначения копии утилиты chown привилегии `CAP_CHOWN`

- `cap_chown` - capability, позволяющая обходить стандартные ограничения при изменении UID и GID владельца файла
- `e` (`Effective`) - capability активна при выполнении программы
- `p` (`Permitted`) - capability разрешена процессу

`sudo -u user1 getcap /home/user1/chown-cap` - для проверки установленной capability

Результат:

`/home/user1/chown-cap cap_chown=ep`

`sudo -u user1 /home/user1/chown-cap root /home/user1/cap-test.txt` - для выполнения привилегированной операции: изменения владельца тестового файла на root пользователем user1 с помощью копии chown с установленной `CAP_CHOWN`

`sudo -u user1 ls -l /home/user1/cap-test.txt` - для проверки результата выполнения операции

После выполнения команды владельцем файла становится root, что подтверждает успешную работу механизма Linux capabilities.


## Раздел 5. Изучение механизма sudo

Требуется разрешить пользователю user1 устанавливать системное время без предоставления ему полного административного доступа.

`sudo visudo` - для безопасного редактирования файла `/etc/sudoers`

В файл `/etc/sudoers` добавлено правило:

`user1 ALL=(root) /usr/bin/date`

Правило разрешает пользователю user1 выполнять `/usr/bin/date` от имени root.

`sudo visudo -c` - для проверки синтаксической корректности файла `/etc/sudoers`

Результат проверки: `/etc/sudoers: успешно обработан`.

`sudo -l -U user1` - для просмотра команд, которые пользователь user1 имеет право выполнять через sudo

В результате подтверждено разрешение:

`(root) /usr/bin/date`

`sudo -u user1 /usr/bin/date 092723402026.00` - для проверки невозможности изменения системного времени пользователем user1 без использования разрешённого механизма sudo

- `sudo -u user1` - запустить `/usr/bin/date` от имени обычного пользователя user1
- результат `Операция не позволена` подтверждает отсутствие у user1 необходимых системных полномочий

`date` - для просмотра текущих системных даты и времени

`sudo -u user1 sudo /usr/bin/date 092800072026.06` - для выполнения привилегированной операции изменения системного времени пользователем user1 через правило в `/etc/sudoers`

- внешний `sudo -u user1` - запускает последующую команду от имени пользователя user1
- внутренний `sudo /usr/bin/date` - использует разрешение user1 на выполнение `/usr/bin/date` от имени root
- успешное выполнение команды подтверждает работоспособность настроенного правила sudo

`date` - для проверки системного времени после выполнения привилегированной операции

`sudo -u user1 sudo /usr/bin/id` - для проверки того, что пользователь user1 не получил произвольные административные права

Выполнение `/usr/bin/id` от имени root было запрещено, что подтверждает ограничение sudo только командой `/usr/bin/date`.


## Проверка сохранения настроек после перезагрузки

После выполнения разделов 1–5 система была перезагружена для проверки требования о сохранении настроек после перезагрузки.

`sudo reboot` - для перезагрузки системы и последующей проверки сохранения выполненных настроек

После загрузки системы выполнены повторные проверки.

`id user1` - для проверки сохранения учётной записи user1, UID 1234 и членства в группе students

В результате подтверждено:

- пользователь `user1` существует
- UID пользователя равен `1234`
- пользователь входит в группу `students`

`sudo chage -l user1` - для проверки сохранения установленного максимального срока действия пароля

В результате максимальное количество дней между сменами пароля осталось равным `90`.

`sudo ls -l /home/user1/cat-suid` - для проверки сохранения владельца, прав доступа и бита set-UID у копии утилиты cat

В результате файл сохранил права:

`-rwsr-xr-x`

и владельца `root`, что подтверждает сохранение установленного бита set-UID после перезагрузки.

`sudo -u user1 getcap /home/user1/chown-cap` - для проверки сохранения файловой capability у копии утилиты chown

В результате:

`/home/user1/chown-cap cap_chown=ep`

что подтверждает сохранение `CAP_CHOWN` после перезагрузки.

`sudo -l -U user1` - для проверки сохранения правила sudo для пользователя user1

В результате подтверждено разрешение:

`(root) /usr/bin/date`

Таким образом, созданная учётная запись, членство в группе, политика срока действия пароля, бит set-UID, файловая capability и правило sudo сохранились после перезагрузки системы.
